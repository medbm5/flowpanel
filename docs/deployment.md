# Deployment

Free-tier setup: **Neon** (PostgreSQL + pgvector), **Render** (backend Docker image), **Vercel** (Next.js frontend),
**GitHub Actions** (CI with the eval gate, deploy after CI). Allow about 30 minutes the first time.

```
browser ──► Vercel (Next.js, /api/* rewrite) ──► Render (Spring Boot, Docker) ──► Neon (Postgres 16 + pgvector)
                                                        └──► OpenAI (live AI profile only, masked text)
```

## 1. Database — Neon

1. Create a project at <https://neon.tech> (region close to the Render region, e.g. Frankfurt), Postgres 16.
2. In the SQL editor of the database, enable the extensions (Flyway also runs `CREATE EXTENSION IF NOT EXISTS`, but the role
   must be allowed to — running it once as the owner avoids surprises):
   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;
   CREATE EXTENSION IF NOT EXISTS btree_gist;
   ```
3. From *Connection details*, copy the connection string (pooled host, `-pooler`), e.g.
   `postgresql://user:password@ep-xxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
   Paste it as-is into `DATABASE_URL`: the backend converts `postgres://` / `postgresql://` URLs to JDBC
   (`DatabaseUrlEnvironmentPostProcessor`). A `jdbc:postgresql://…` URL with `DATABASE_USERNAME` / `DATABASE_PASSWORD` also works.
   Keep `DB_POOL_SIZE` small (5) on the free tier.

Flyway creates the schema and the demo seeder fills it on first start.

## 2. Backend — Render

1. Push the repository to GitHub.
2. Open <https://render.com/deploy?repo=https://github.com/medbm5/flowpanel> (or **New → Blueprint** and select the repository);
   Render reads [`render.yaml`](../render.yaml) (Docker, free plan, health check `/actuator/health`, `autoDeploy: false`).
3. Fill the secret env vars when prompted:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon connection string (`postgresql://…?sslmode=require`) |
   | `AI_PROFILE` | `mock` (default) or `live` |
   | `OPENAI_API_KEY` | only for `live` |
   | `AI_DAILY_BUDGET_USD` | `2` (live calls are refused above this, per UTC day) |
   | `JWT_SECRET` | generated by Render (≥ 32 bytes) |
   | `CORS_ORIGINS` | your Vercel URLs, with `https://`, comma-separated; `*` patterns allowed for previews, e.g. `https://flowpanel.vercel.app,https://flowpanel-*-<team>.vercel.app` |

4. *Settings → Deploy Hook*: copy the URL and store it as the GitHub secret `RENDER_DEPLOY_HOOK_URL`.
   Optionally set the repository variable `BACKEND_URL` (e.g. `https://flowpanel-backend.onrender.com`) so the deploy workflow waits for health.

The image is sized for the 512 MB free instance: `-XX:MaxRAMPercentage=70 -XX:+UseSerialGC -XX:TieredStopAtLevel=1`
(measured ≈ 240 MB resident after start-up).

## 3. Frontend — Vercel

1. In Vercel: **Add New → Project**, import the repository, set **Root Directory** to `frontend` (framework auto-detected: Next.js).
2. Environment variables (Production and Preview):
   - `BACKEND_URL` = the Render URL (used by the `/api/*` rewrite on the server; the browser never calls Render directly, so the
     session cookie stays first-party on the Vercel domain).
   - `NEXT_PUBLIC_SITE_URL` = the Vercel URL (metadata, Open Graph, sitemap).
   - `NEXT_PUBLIC_GITHUB_URL` = the repository URL (footer link).
3. Vercel's Git integration deploys every push: previews for pull requests, production for `main`. To deploy production only after CI
   passes, enable *Settings → Git → Ignored Build Step* with `exit 0` for non-`main` branches, or protect `main` with the CI checks
   (recommended: *Branch protection → Require status checks: Backend, Frontend, Eval suite, Playwright smoke*).

## 4. OpenAI (live profile)

1. Create a project API key at <https://platform.openai.com> and set it as `OPENAI_API_KEY` on Render (and as the GitHub secret
   `OPENAI_API_KEY` for the manual *Live evals* workflow).
2. **Set a monthly usage limit in the OpenAI dashboard** (*Settings → Limits*), e.g. $5 — a second safety net on top of the
   application's `AI_DAILY_BUDGET_USD` and per-tenant rate limit.
3. Switch `AI_PROFILE=live` on Render and redeploy. The admin dashboard shows spend today vs budget; when the budget is reached, the
   gateway refuses live calls with `ai_budget_exceeded` and the UI shows the message.
4. Run *Actions → Live evals → Run workflow* to score the live models (manual only, to protect credits).

## 5. CI/CD summary

| Workflow | Trigger | What it does |
|---|---|---|
| `ci.yml` | pull requests, pushes to `main` | backend `./mvnw verify` (Testcontainers), frontend lint / typecheck / test / build, eval suite in mock profile (fails under thresholds), Playwright smoke against a mock backend |
| `live-evals.yml` | manual | eval suite against the deployed backend in live profile, optional LLM judge |
| `deploy.yml` | after `CI` succeeds on `main` | calls the Render deploy hook, waits for `/actuator/health` |

## 6. Before a demo — free-tier cold start

Render's free instances sleep after 15 minutes without traffic and take 30–60 s to wake up (Neon also suspends idle compute).
**Open the app a minute before the demo** (or `curl https://<backend>/actuator/health`). To start from fresh data, sign in as the admin
persona and click *Reset demo data* (or `POST /admin/demo/reset`).
